# Von der Idee zur Spec

## Worum es geht

Ein Prompt beschreibt einen Wunsch. Eine Spec beschreibt ein Ergebnis. Der Unterschied ist der Grund, warum manche Leute mit Agents in zwei Tagen etwas Brauchbares bauen und andere nach zwei Tagen 3.000 Zeilen haben, die nicht laufen.

Vier Abschnitte genügen: Ziel, Abgrenzung, Akzeptanzkriterien, Technik.

## Starten

`spec-vorlage.md` kopieren, ausfüllen, in euer Projekt legen (z. B. `specs/`). In `beispiel-favoriten.md` steht eine fertige Spec als Maßstab.

## Ins eigene Projekt

Ab Blatt 8 Pflicht: **eine** Spec für das letzte Feature, das ihr baut. Sie darf kurz sein – eine halbe Seite reicht –, aber sie muss vor dem Code entstehen.

Der Nutzen ist doppelt: Der Agent weiß, was zu tun ist, und **ihr** habt hinterher eine Checkliste, an der ihr das Ergebnis prüft. Ohne Akzeptanzkriterien gibt es kein „fertig", nur ein „sieht gut aus".

## Der wichtigste Abschnitt

„Nicht Teil davon". Modelle ergänzen lieber, als wegzulassen. Wer nicht sagt, was nicht gebaut werden soll, bekommt ein Login, eine Datenbank und drei Einstellungsseiten geschenkt.

## Änder mich

1. Schreibt die Spec für ein Feature eures Projekts. Gebt sie einer KI mit dem Auftrag: „Stell mir fünf Rückfragen zu dieser Spec." Die Fragen zeigen euch, was noch unklar ist.
2. Vergleicht: Lasst dieselbe KI das Feature einmal aus einem Einzeiler bauen und einmal aus eurer Spec. Welches Ergebnis könnt ihr besser prüfen?
